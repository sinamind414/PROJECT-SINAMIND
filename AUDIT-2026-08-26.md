## 3. Critiques (P0)

### P0-1 — IDOR Bac Blanc

`routes/bac_blanc.py` : `choose`, `save`, `submit`, `GET /{session_id}/correction` filtrent par `id` de session **sans `user_id`**.

N’importe quel élève authentifié qui itère des UUID/ids lit les copies, écrit les réponses, soumet et récupère la correction d’un autre.

`start` insère bien `user_id` — il n’est ensuite jamais relu.

### P0-2 — Économie et scores client-trusted

Aucune borne serveur :

| Endpoint | Effet |
|---|---|
| `POST /api/gamification/points/add?points=` | `total_points += points` sans max (`gamification_service.py`) |
| `POST /api/avatar/add-xp?xp=` | idem XP / niveau |
| `POST /api/phase5/challenge/{id}/result` | le client envoie `score` / `correct_answers` |
| `POST /api/duels/{id}/answer` | le client envoie `score` |

Leaderboard, gemmes dérivées, duels et « live classroom » sont **falsifiables en une requête**. Ce n’est pas un détail cosmétique si ces chiffres sont affichés nationalement.

### P0-3 — Annales PDF = pointeurs Git LFS (131 octets)

```
khawarizmi-frontend/public/pdfs/bac-svt/*.pdf     → 131–132 octets
khawarizmi-frontend/public/pdfs/bac-svt-math/*.pdf
```

Railway / Vercel **ne pullent pas LFS** par défaut. Les sujets/corrigés 2023–2026 sont cassés en prod et dans ce clone. Même constat pour le modèle ONNX si le zip LFS n’est pas matériel.

### P0-4 — CI ne protège pas `main`

`.github/workflows/ci.yml` :

- déclenché seulement sur `main` / `fabuleux/*` / PR vers `main` — **pas cette branche**
- backend : ~6 fichiers `test_methodology*`…, **pas** la suite (91 fichiers)
- `REDIS_URL` pointé, **aucun service Redis**
- lint front : `continue-on-error: true`
- `deploy-railway` après ces checks faibles

Un merge peut republier une régression du type `app_state` sans qu’un check ne rougisse.

## 4. Élevés (P1)

### P1-1 — `/api/auth/refresh` fantôme

Le client (`api-client.ts`) retry les 401 via `POST /api/auth/refresh`. **Aucune route refresh** dans `routes/auth.py`. Après 24 h (`JWT_EXPIRE_HOURS`) : logout forcé, pas de rotation, pas de `jti`, pas de révocation. Le JWT est aussi renvoyé **dans le body JSON** (XSS → vol de session).

Le rate-limiter (`rate_limit.py`) ne lit que `Authorization`, **pas le cookie** `khawarizmi_access_token`. Un élève cookie-only est limité par IP, ou pas du tout s’il est derrière un NAT de lycée.

Cookie prod : `SameSite=None; Secure` (nécessaire Vercel → Railway). Sans CSRF token, les POST JSON sont protégés par preflight CORS ; les GET authentifiés par cookie restent cross-site *sendable*.

### P1-2 — Fuites pédagogiques (triche)

1. `GET /api/lessons/{slug}` renvoie `quick_check.correct_index` et `expected_keywords` (`lessons.py` + `schemas/lesson.py`). Le QCM est corrigé côté client.
2. `GET /api/document-analysis/scenarios/{slug}/correction` livre les `model_answer_ar` à **tout JWT**, sans preuve qu’une évaluation a eu lieu.
3. `POST /api/aujourdhui/valider` renvoie `bonne_reponse_index`.

### P1-3 — Vie privée élèves

- `GET /api/phase5/users/search` → `id, email, prenom, filiere` (`phase5_service.py:159`).
- `list_friends` renvoie aussi l’email.
- `da_answers.answer_text` stocké **en clair**. `hash_answer()` (HMAC-SHA256) existe et n’est **jamais appelé** hors tests / hash de prompt. La promesse RGPD du README est fausse.
- Waitlist (`POST /api/waitlist`) : crée un user + mot de passe aléatoire + cookie JWT, **sans auth**. Surface de flood de comptes.

### P1-4 — Split auth front : `fetch` natif vs `apiClient`

Pages **shop, map, leaderboard, duel, achievements, gems, streaks** appellent `fetch("/api/...")` **sans** `Authorization` et souvent sans s’appuyer sur le client central.

Si `NEXT_PUBLIC_API_URL` pointe vers Railway (suggéré par la CSP `connect-src … railway.app`), le cookie est sur le domaine API ; `fetch("/api/…")` tape Vercel → **401 silencieux**. Ces pages « marchent en local » (rewrite) et cassent en prod.

Second client mort : `khawarizmi-frontend/lib/api-client.ts` (273 lignes, URL Railway en dur, `/auth/login` sans préfixe `/api`). Non importé par `src/` — piège pour le prochain agent.

### P1-5 — Cache chatbot cross-élèves

`routes/chatbot.py` : clé Redis = prompt + modèle + langue + mode + chapitre + bucket pédagogique + **message**. Pas de `user_id`. Deux élèves qui posent la même question reçoivent la même réponse (y compris personnalisation / sources).

### P1-6 — Aujourd’hui hors base

`routes/aujourdhui.py` persiste la maîtrise dans `data/mastery/{user_id}.json`. Sur Railway (multi-instances, FS éphémère) : progression perdue au redeploy, non partagée entre replicas. `data/` est dans `.gitignore` mais 36 fichiers `data/` restent trackés.

### P1-7 — Uploads sociaux orphelins

Fichiers écrits dans `uploads/social/` — **aucun `StaticFiles` monté**. `file_url` renvoyé = 404. Disque éphémère Railway.

### P1-8 — Endpoints debug / métriques publics

Sans auth :

- `GET /debug/data-foundation`
- `GET /api/metrics`
- `GET /api/calibration/stats`
- `GET /metrics/prometheus`
- `GET /health` expose `environment`, chemins de backup, comptes métier

Utile en ops, trop bavard en prod ouverte.

### P1-9 — CSP / Permissions-Policy vs produit

`next.config.ts` :

- `Permissions-Policy: microphone=()` → le bouton voix de `VerbLessonFlow` est **bloqué** en prod.
- `connect-src` figé sur un seul host Railway — tout autre backend (preview, custom domain) est coupé.
- `script-src 'unsafe-inline' 'unsafe-eval'` annule une bonne partie de la CSP.

## 7. Ce qui est vraiment bon

1. **`llm_guard.py`** — double opt-in, scrub des clés, blackhole httpx, client muré. Meilleur module de sécu du repo.
2. **Pipeline `grading/`** — sanity → savoir → LLM → parse → fallback L2 ; cache hors pipeline ; observabilité prévue.
3. **Auth unique JWT**, cookie httpOnly, `SECRET_KEY` obligatoire hors CI, OpenAPI coupé en prod.
4. **SQL paramétré** (pas de concat). `ANY` / `bindparam(expanding=True)` utilisés.
5. **Paiement Chargily** : HMAC + idempotence sur `checkout_id`.
6. **Dégradation gracieuse** Redis / DB / embedder.
7. **Contrat FE/BE réparé** — le travail de ré-enregistrement (`aujourdhui`, `lessons`, `bac_blanc`, stream chatbot) a tenu.
8. **Moteur local** : le produit peut vivre sans clé LLM. C’est rare et c’est la bonne stratégie Bac.
